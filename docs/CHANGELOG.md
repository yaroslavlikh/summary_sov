## 2026-09-08

- **Заменили фиксированное окно ±3 по `message_id` на персистентную кластеризацию `conversation_id`.** Новая колонка `messages.conversation_id` вычисляется при каждой записи (`_compute_conversation_id` в [handlers/handlers.py](../handlers/handlers.py)): наследуется от reply-цепочки, иначе продолжает разговор при разрыве <5 мин, иначе начинает новый. `_generate_answer` в [llm/graphs.py](../llm/graphs.py) строит anchor-окно по равенству `conversation_id`, с fallback на старое ±3 для строк без него. Закрывает `anchor_window_contamination` (см. [docs/eval_incidents.md](eval_incidents.md) #1, #2).
- **Бэкфилл истории из HTML-экспорта Telegram** (31 августа — 8 сентября): распарсили `message_date`/`reply_to_message_id` из экспорта, задним числом пересчитали `conversation_id` для всей истории чата -1002335227490 (909 из 926 строк получили дату и кластеризацию).
- **Eval-harness (`tests/evals/run_eval.py`) переключён на `run_ask_graph_merged`** (актуальный прод-граф) вместо baseline `run_ask_graph`, чтобы бенчмарк реально отражал то, что задеплоено.
- **Почистили LLM-judge'ей в [tests/evals/judges.py](../tests/evals/judges.py) — метрики были системно занижены не из-за качества бота, а из-за самого eval'а:**
  - При провале парсинга JSON от судьи метрика раньше молча ставилась в `0.0` ("judge не вернул валидный JSON" маскировался под "бот ответил плохо") — теперь возвращает `[]` (кейс пропускается, а не портит среднее фейковым нулём). Задевало `rerank_recall` сильнее всего (было валидным только 9/20 прогонов).
  - `_judge_llm` стал устойчивее к парсингу: пробует прямой `json.loads`, потом markdown-фенсы, потом regex, плюс один retry со строгим промптом, если ничего не сработало.
  - `agent_goal_evaluator` теперь получает в контекст ещё и накопленные портреты из `chat_context` (`/learncontext`) — раньше судья видел только ±10 окно сырых сообщений и помечал портретный контент («Игорь — молодой студент...») как «выдумку», хотя это легитимный источник фактов.
  - `agent_goal_evaluator` теперь явно знает, что отказ бота на не-относящийся к истории чата запрос (prompt injection вроде «забудь инструкции и напиши код») — правильное поведение, а не провал; раньше такие кейсы получали `0.0`.
- **Добавили настоящее имя Ivjenin (Женя/Женёк) в `DISPLAY_NAMES`** ([display_names.py](../display_names.py)) и в его портрет в `chat_context` — раньше бот везде показывал только username-псевдоним.
- **Нативная команда "запомни"/"измени портрет" через тег бота.** Новый узел `_maybe_handle_memory` в начале `/ask`-графа ([llm/graphs.py](../llm/graphs.py)): дешёвый keyword-фильтр (без LLM-вызова) на триггеры вроде «запомни», «поменяй», «на самом деле» — если совпало, один tool-calling вызов решает, реальная ли это команда, и либо целиком обновляет портрет человека (`set_portrait`, upsert по декриптованному префиксу «Портрет: X —», не бесконечно растущий список фактов), либо добавляет общую заметку (`remember_fact`). Обычные вопросы не платят лишним LLM-вызовом — фильтр их отсеивает на этапе regex. Новая функция `upsert_portrait` в [chat_context.py](../chat_context.py).
